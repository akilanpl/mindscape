# Transfer approval matrix

All new numerical choices: PROPOSED_REQUIRES_FREEZE_AND_REVIEW.

| Stage | Required external evidence | Current state |
|---|---|---|
| Candidate/source/runtime freeze | Signed exact loss/Adam/permutation/bootstrap/schedule/generator/executor/asset/runtime commitments | Proposed, not approved |
| One deterministic24/12/24 draw per domain | Separate human data authorization, immutable historical exclusion and target custody | NOT AUTHORIZED / UNRUN |
| One qualification screen | Locked independent WASI/Pymunk/register outcomes, exact frozen qualification gates | UNRUN |
| Training | Separate later signed human authorization after successful bound DATA_READY qualification; native MPS | NOT AUTHORIZED / BLOCKED |
| Composition outcomes/scoring | Nine independently signed final checkpoint and raw prediction seals | UNRUN |
| Confirmation | All mandatory gates, retained failures and independent review | UNRUN |

NativeCallbacks accepts external authority and custody implementations. These are trusted operational boundaries, not self-authenticating receipt strings. A verifier must reject missing/expired/wrong-scope signatures, substituted source/runtime/data, reused qualification receipt, or self-signed local approval. No production signer or protected data provider is provisioned by this sprint. The candidate is implemented for review and synthetic verification, not deployment-ready scientific execution.
