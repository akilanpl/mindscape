# Mindscape V3 Python debugging research report

This report separates an implemented research workflow from evidence that its concept mechanism improves generalization. The learner proposes Python source; the preserved WASI sandbox executes it; visible tests guide retries; an independent terminal scorer measures held-out success. No hidden patch enters the learner and no generated program runs in host Python.

## Scope and preservation

The work is on `development/v3-coding-learning`, based on V3 foundation commit `432c20f`. Original coding implementation, V1/V2 experimental archives, adapters, WASI source/runtime, historical lockbox and release tags are protected. The new implementation is in `mindscape.v3.coding_learning`; additional research drivers live under `scripts/v3_coding`. Preservation checks compare every pre-V3 tracked blob and all release tags, plus a starting inventory of845 external backbone/adapter/runtime/old-lockbox files. The historical lockbox is hashed, never opened or rerun. Saved historical result traces are used for the audit below.

This is a bounded synthetic Python repair study, not a real-project coding benchmark, general intelligence result or reasoning breakthrough. The local Qwen2.5-Coder-1.5B-Instruct backbone stays frozen. Three small proposal-evaluator checkpoints were actually trained. No new Qwen LoRA training is claimed.

## Why historical C did not improve OOD

Saved historical rows reproduce B's24/50 OOD and45/50 IID successes, and C's18/50 OOD and49/50 IID successes. These percentages concern the original benchmark only. The new benchmark percentages must not be compared directly to historical48%.

Both conditions made800 model calls over100 episodes. B proposed592 edits and had208 unparsed actions; C proposed800 edits. The traces contain333 B edit-budget errors and500 C edit-budget errors. Neither condition emitted test actions or visible-test-pass events. OOD first-edit correctness was12 for B and18 for C; final correctness was24 and18. B changed a wrong first edit into a successful final repository on12 OOD tasks, C on zero. This first-versus-final metric is not evidence of feedback-guided self-correction, because neither executed visible tests. C applied only one distinct repository in every OOD episode; B applied two distinct repositories in12 episodes and one in38.

The original memory uses specification-word Jaccard overlap. Its planner assigns fixed scores (edit0.7 versus test0.5), without learned repair semantics. Original supervised tool examples emphasize edits rather than test/finish actions. The observed C behavior therefore does not demonstrate an executed hypothesis/feedback cycle: repeated edits and exhausted budgets explain why extra calls could fail to improve its first proposal.

This is an evidence-backed diagnosis of behavior, not a causal claim that memory harms learning. B-only OOD successes12 and C-only6 give exact paired McNemar p=0.2378845; IID discordances1 versus5 give p=0.21875. Training, adapters and other historical differences remain confounded. Full audit, first-edit and edit-diversity receipts are retained.

## Implemented learning workflow

The agent performs READ/REPRESENT → HYPOTHESIZE/PROPOSE → PREDICT → ACT/OBSERVE → UPDATE working evidence → RETRY/STOP. Typed records describe contracts, invariants, repairs, hypotheses and provenance. Python AST inspection extracts nodes, branch/loop edges, lexical definitions/uses, assignment dependencies, imports and mechanism hypotheses. This is approximate static analysis, not complete control-flow, alias or semantic analysis.

Persistent memory admits only approved training identities and actually successful visible and training-private executions. Loading memory re-executes those repairs rather than trusting a saved success Boolean. Evaluation changes working evidence only. Structured cosine retrieval compares35 AST/operator/control/invariant features; the word-memory condition preserves a simple lexical comparison. Detailed AST graphs remain inspectable, but retrieval does not perform full graph matching.

The learned evaluator has3,682 parameters and112 inputs: before/after/delta structural features and seven syntax/edit/memory fields. It estimates visible-test usefulness and execution cost. Private success is always unknown. A bounded planner selects among at most two Qwen proposals using usefulness minus0.01×predicted seconds. No-planning selects candidate zero. This is learned proposal ranking, not a learned long-horizon policy.

Existing-file replacements are atomic, up to four Python files and16,000 characters per file. Paths, unsupported imports and reflective execution capabilities fail closed. These are syntactic/capability restrictions, not exact semantic action masks: even a single allowed file admits many wrong replacement programs. The negative executed controls demonstrate that the controller does not supply a successful repair by restricting choices to the answer. The original WASI implementation supplies guest isolation, fuel/time/memory/output limits and restricted filesystem capabilities. Host parsing is allowed; host execution/import of proposed code is forbidden. Host comparison checks values and top-level output types, with guest post-call snapshots for specified mutation invariants. Private expected outputs are absent from guest code. Final review reproduced indirect `__builtins__` access inside WASI and nested bool/int equality in the frozen comparator. An additive versioned `GuardedExecutor` rejects dunder identifiers/definitions and checks recursive output/mutation types. The original study source stays immutable; independent guarded replay checks whether these fixes alter recorded outcomes. This is not a proof against every adversarial guest forging observations; the bounded capability policy and sandbox are the security scope.

## Benchmark and experimental chronology

The original new benchmark and model code froze at commit `38a8494`, before model evaluation. It has24 training,6 validation,6 IID and12 structural-OOD tasks. Six OOD families each have two tasks: cross-file dependencies, compound predicate/identity bugs, unfamiliar while-loop control flow, renamed identifiers, alias mutation through a helper, and order/boundary composition. All defects and references were actually executed against visible and private suites,192 executions. An empty-input generator initially lacked a failing private case; validation caught and fixed it before freezing.

The scalar run completed79/144 episodes before its CPU cap; the initial batched pilot completed16/144 before a throughput/cancellation abort. All saved episodes failed. These are incomplete failed transport pilots, not a complete generalization score or evidence that concept reasoning failed. Their raw responses, source identities and resource receipts are preserved. The initial threaded cancellation problem was reproduced and fixed in a new research coordinator; historical code was untouched.

A training-only diagnostic replaced the fictitious filename example with explicit allowed paths. It never rewrote model outputs or source code. Three of six training-family examples then passed both visible and private tests. To avoid treating an adapted prompt on exposed holdouts as confirmatory evidence, a fresh V2 panel was generated from the unchanged generator and parameter bounds, excluding all V1 holdout task identities/parameters. It reuses exactly the same24 training and6 validation tasks, and introduces18 fresh held-out tasks (6 IID/12 OOD). Seventy-two new defect/reference validations passed. No new training examples or Qwen updates were added; the60% target, families, difficulty, scoring and budgets stayed fixed.

V2 froze before any V2 model call. Public manifest SHA256 is `2cea9083ecaf9c42f2a6cfd72f5e31a57964482596ab9d1648fec9f1b9e5fcc7`. The final protocol binds the explicit-path transport, CPU batch runner, driver and cancellation coordinator hashes. It freezes primary evaluator seed11, secondary23/37, a10-percentage-point meaningful gain, and a paired bootstrap interval excluding zero over the strongest reference condition. Source freeze and chronology receipts are retained. V2 is a follow-up study informed by V1's transport failure, not the original untouched protocol.

Public/private separation is logical and tested; new private researcher JSON is not cryptographically sealed. Task IDs are disjoint but templates/local mechanisms intentionally overlap. Foundation pretraining contamination cannot be excluded. Renaming is combined with fresh parameters rather than isolated as a paired rename-only experiment.

## Training and fair comparisons

Each evaluator uses96 actual training-visible labels from24 tasks: a reference repair, unchanged source, invalid syntax and wrong constant-return proposal. There are24 positive rows. Training memory admission and labels require120 actual WASI calls, excluding pre-execution syntax rejection. Retrieval features leave out the current training task. Each seed trains400 full-batch Adam updates,38,400 labeled-row presentations per seed (not38,400 distinct examples). The frozen evidence records intermediate losses, measured runtime labels and checkpoint hashes. Reproduction from those exact labels can reproduce weights; rerunning execution produces different runtime labels and need not reproduce cost weights bitwise. Evaluator optimizer-state continuation is not implemented.

All eight conditions use the same frozen Qwen snapshot, greedy CPU float32 decoding, at most two model calls,256 new tokens per call, at most two candidate proposals and the same visible feedback. Plain/structured/typed receive two fixed approved examples from the same24-task pool (both threshold examples because the frozen loader takes the first two, an important baseline weakness); memory variants retrieve two. No-memory removes runtime examples. No-concepts also changes retrieval to words and zeros structural evaluator inputs. These are practical inference interventions, not perfectly equal-token architecture-only contrasts. The simple baselines do not use the96 labels in a trained scorer, so the study does not establish equal-information *trained* baseline superiority. Logical input/output token totals, including cache-reused requests, expose prompt differences separately from fresh compute. No-planning retains the identical memory/prompt path to Mindscape and provides the clearest paired selection intervention; its efficacy still depends on what candidates Qwen proposes.

Stop decisions depend only on visible pass or budget. Final private outcomes and first-edit correctness are scored after the agent terminates. Cache entries contain actual raw Qwen responses and hashes; no synthetic response is substituted. All conditions use the same batch wrapper. A training-only throughput probe found two scalar requests9.4754s versus a batch6.7106s with identical raw responses; this is not a proof of batching invariance for every prompt. All headline V2 conditions share the same numerical stratum. Exact cached responses and executed outcomes are replayable; fresh asynchronous batch scheduling is not guaranteed to regenerate bitwise-identical Qwen text across hardware or batch shapes. This limits strict from-scratch actor determinism and motivates a fixed scheduling protocol in future work. One legacy prose field in the runner identity still says `unchanged frozen-v1`; the authoritative `path_schema_remediation=true`, protocol-bound helper hashes and saved `actual_model_payload` identify the revised model-visible transport.

## Falsification and revised hypothesis

A post hoc **training-only** test changed a correct accumulator initialization from1 to2. Both proposals produced exactly the same112 evaluator features, hence exactly the same predicted usefulness0.9947811 and cost0.3193457 seconds. Actual WASI execution passed the correct repair and failed the wrong one. Strong training loss therefore does not imply semantic repair evaluation: this literal-blind representation cannot distinguish a crucial identity constant. The training negatives are also simpler than plausible Qwen mistakes: unchanged source, invalid syntax and constant returns permit a shortcut based on whether a small valid edit occurred. A wrong literal edit can look like the expert edit under these features. Extrapolation/calibration must therefore be judged on actual proposals rather than training loss.

A separate post-freeze validation diagnostic used18 executed proposals (six teacher, six unchanged, six near-miss) on six validation tasks, with no updates. Each seed classified14/18 at threshold0.5; seed11 Brier=0.20874, AUC=0.86806 and runtime MAE=0.25537s under concurrent local load. All four classification errors were near misses: near-miss accuracy was2/6, versus12/12 on the teacher/unchanged proposals. The aggregate score therefore masks the hard semantic-discrimination weakness. This tiny constructed validation set is not repair-rollout accuracy or evidence of calibrated OOD planning.

A post-freeze initial-retrieval audit also found a limitation: structured top-two retrieval included at least one expected generator-mechanism family on10/12 OOD tasks, versus12/12 for word retrieval. Both covered6/6 IID tasks. Requiring all expected mechanisms (two for compound tasks, one otherwise) gave8/12 versus10/12 overall. Both while-loop OOD queries retrieved two accumulator examples rather than range-sum examples: count similarity favored syntactic form over intended behavior. Repeated contract wording also makes word overlap unusually strong here; the benchmark does not isolate contract-paraphrase OOD. These family-overlap counts are a diagnostic proxy, not semantic relevance ground truth or proof of a causal repair effect.

A revised hypothesis is to encode literal values, operator roles and contract-conditioned relationships, and train on executed, plausible candidate pairs collected from training tasks. A future study should supply equal labels to same-backbone learned baselines, distinguish retrieval benefit from proposal selection, include more multi-candidate decisions, and freeze a new larger holdout before any revised model evaluation. This revision is not implemented or tuned on V2 outcomes in this delivery.

## Decision and handoff

**GO** for using this bounded, tested workflow as a research platform with the additive safety guard. **NO-GO** for claiming that explicit concepts improve OOD debugging, that the superiority target is achieved, or for moving to larger domain training on that premise. The evaluator and retrieval diagnoses explain concrete weaknesses and justify a new frozen study, not tuning this holdout.

Runnable source, frozen manifests/protocols, actual evaluator weights, raw traces, statistical summaries, complete failures, preservation receipts and reproducibility commands accompany this report. `README.md` gives the exact workflow; `architecture.md` gives interfaces and trust boundaries. The evidence archive is hash-verified and independently replayable through WASI without Qwen inference. Remaining limitations include tiny synthetic holdouts, incomplete feedback for module/import errors whose raw stderr is retained but not always passed to the model, incomplete adversarial scorer hardening, simple structural features, candidate-distribution mismatch, no new Qwen LoRA training, no optimizer-state training resume, and no claim that this system meets the full long-term concept-learning ambition.
