# R6 programming semantics audit

The frozen R5.7c coding task asks for the index of a requested variable name in a candidate list (`src/mindscape/r57/data.py`, `labels`). Its model has a candidate pointer using query/candidate name embeddings (`src/mindscape/r57/model.py`). Exact string matching can solve this target without executing the source program. Candidate permutation tests assess name/index behavior, not execution semantics. This source inspection does not establish a new trained-model result.

R6 replaces that objective with integer output prediction for original, bounded Python functions. Four foundation structures cover affine expressions, accumulator for loops, bounded while loops, and conditionals. Three final structural OOD families contain nested loops, nested functions, or conditionals inside loops. Identifier/function names, literals, and valid indentation vary. An AST encoder representation is saved as metadata, while the neural input is program text and the target is an integer string. No answer candidates exist, so candidate positions, candidate-order invariance, and distractor randomization are not applicable; the decoder cannot select an answer position.

Labels agree between a restricted AST interpreter and separate closed-form formulas for every generated record. Tests additionally compare a sample of trusted generated templates with isolated, timeout-bounded CPython. The dataset generator never evaluates arbitrary Python using eval/exec, imports model code, or runs optimizer updates. The AST interpreter supports only its explicit integer/function/control-flow whitelist, bounds ranges and integer arithmetic, and has a 10,000-step budget. Invalid, unsupported, or nonterminating programs are rejected. Interpreter scores are external exact-reference scores, not neural competence.

Train, development, and IID final splits use disjoint literal-coordinate residue classes, even across different generation seeds. Final OOD additionally uses unseen program templates. Canonical keys parse syntax, alpha-rename bindings, discard whitespace/location information, and retain literal values and AST structure; exact canonical duplicates are rejected within generation. This is syntactic alpha-equivalence, not proof of equivalence for all algebraically equivalent programs. Cross-domain manifest checks must still enforce global uniqueness. The generator caps each split at 1,000 examples and exposes rejection-budget failure instead of silently producing undersized datasets.

Perturbations include identifier renaming, source reformatting, an equivalent positive-input branch wrapper, and answer-changing function-input interventions. Same-answer perturbations test robustness; literal interventions test dependence on input values. All targets are recomputed with both verifiers. These probes are scored independently from the primary held-out metric and do not alter a neural prediction. OOD results must be reported by template alongside exact output accuracy and these robustness scores.

This pilot does not implement list/dictionary semantics, searching/sorting, recursion, files, CSV, exceptions, stacks, SQL, databases, natural-language programming questions, or unrestricted code generation. Nested-function/loop execution is prerequisite evidence only. No CBSE Class 12 programming competence can be inferred from passing generator tests or from the deterministic interpreter reaching 100%.
