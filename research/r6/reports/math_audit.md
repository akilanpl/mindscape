# R6 mathematics foundation audit

## Observed historical behavior

Inspected `src/mindscape/r57c/ordinal_model.py`, the inherited `src/mindscape/r57/model.py`, and the actual preceding `outputs/CLOUD_COMPARISON.md`. In R5.7c, `OrdinalCandidate.forward` returns directly for mathematics before calling the graph or recurrent core. Two operation-specific rows of four trainable weights consume normalized left/right digits, observed incoming carry/borrow, and a constant. A learned scalar is decoded against fixed ordinal centers; digit and carry heads marginalize the resulting fixed label geometry. This is a learned operand-dependent linear predictor, **not** an input arithmetic oracle and **not** an operand-independent constant classifier. It does bypass the intended graph reasoning mechanism. A graph-versus-GRU difference in these math scores therefore cannot establish a graph arithmetic advantage.

The R5.7c task only supports one decimal column, addition or borrow subtraction, and an incoming bit. Output classes cover the limited single-column range. The inherited R5.7 math features use one-hot digits and a graph state, but that path is bypassed by R5.7c mathematics. Neither implementation represents arbitrary expression trees, multiple columns, recursive carry propagation, signed multi-digit outputs, multiplication, or Class 12 concepts.

The verified historical comparison reports graph-on and graph-off CUDA mean math exact accuracy 0.129944, and matched-GRU 0.186441, each over three exploratory seeds. The graph conditions span 0.101695–0.152542 and the GRU 0.135593–0.237288. These are reused historical holdouts, not new R6 evidence. CUDA reproduced the historical R5.7c math scores. A restricted linear scalar can in principle represent the single-column arithmetic target; the observed accuracy does not identify a unique optimization cause. No unmeasured gradient, convergence or data-coverage diagnosis is asserted here. Learning a continuous scalar while evaluating sharp ordinal decisions, sparse small training coverage, and conditioning differences are hypotheses for controlled measurement, not proven explanations.

## Implemented foundation generator

`research/r6/datasets/mathematics.py` provides `generate(split, seed, count)` and `generate_with_metadata(split, seed, count)`. The first three splits use signed two-digit addition, subtraction and multiplication with balanced operator sampling. The input contains only the expression and observed operands/operators. Targets are canonical integer strings. `features` is empty. No answer, carry annotation, numerical solution feature or reference execution trace enters model observations.

Canonicalization flattens associative sums/products, normalizes subtraction into signed sums, and orders commutative children. It intentionally does not collapse distinct problems to their equal answers. Stable SHA-256 partitions of canonical expressions allocate train, development and final IID contexts to separate buckets; even identical generation seeds cannot overlap across these splits. These splits deliberately share structural templates and operand ranges to measure new operand combinations. Template overlap is expected and must be reported, not presented as structural separation.

Final OOD alternates (a) binary expressions with operand magnitudes 100–9999, absent from two-digit training, and (b) left-parenthesized three-operand expressions with two-digit operands. This separates a magnitude stress test from a compositional structure stress test. Both have explicitly different template identifiers. Final generation is deterministic from its recorded seed. The evaluator must receive final records separately; keeping them out of trainer attachments remains the integration controller's responsibility. Shared account ownership does not constitute strong access control.

`reference_answer` traverses a restricted Python AST using `fractions.Fraction`; `structured_answer` applies independently implemented integer operators to observed operand/operator lists. Generation aborts on any disagreement. No `eval`, `exec`, arbitrary Python import, external network, optimizer or training dependency is used. The verifier additionally matches text, expression, operand structures, target and canonical key. Invalid syntax/operators/types/oversized constants are rejected. Generator metadata records accepted count, attempted draws, canonical duplicate and partition rejection counts, templates, topics and maximum input byte length. Unsupported split/count types and exhausted practical capacity raise explicit errors rather than silently returning partial data.

`carry_borrow_category` supports evaluation-only strata for nonnegative binary addition/subtraction, with separate signed/multiplication/compositional categories. It must not be added to neural input. Zero constant predictors and exact algorithmic references should be reported separately from neural accuracy. Exact arithmetic oracle correctness is a generator check, never evidence of neural reasoning.

## Scope and next architecture measurements

This implements a limited M1 pilot. Division, decimals, fractions, general operator precedence, equations, matrices, derivatives, calculus, probability and all remaining Class 12 topics are uncovered. Parenthesized OOD compositions are held-out stress cases; no reliability is assumed before evaluation.

A token/sequence output model must learn sign and decimal digits from observed symbols and compare against a matched recurrent baseline on identical rows, steps and seeds. Future typed-expression graph work should make operator identity and parent/child edges explicit, preserve operand order for subtraction, and test their removal under matched parameter and compute budgets. Carry-state supervision would be a separately named ablation with generated labels, never a hidden inference algorithm. Broad curriculum promotion requires improvement beyond initialization and trivial baselines on development, followed by protected structural evaluation. This audit reports no R6 fit or R6 performance metric.
